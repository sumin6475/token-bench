## 가설 A — 로컬 24~35B급으로 잘 될 것

- 요약, 번역, 문체 교정, 리라이팅, 분류/추출
- 일상 코딩 보조 — 함수 짜기, 버그 설명, 코드 리뷰, 정규식/SQL
- 브레인스토밍, 초안 잡기, Q&A, 문서 기반 답변(RAG)
- 프라이버시 필요한 작업 (데이터가 기기 밖으로 안 나감)

## 가설 B — 로컬로 약하거나 안 될 것 (당분간 클라우드)

- 길고 자율적인 에이전트 작업 (여러 단계 tool use로 오래 자율 실행) — 로컬의
  tool-calling이 약점. Claude Code 완전 대체는 어려움
- 최전선 추론 — 어려운 수학/알고리즘, 복잡한 다단계 논리
- 아주 긴 컨텍스트 (큰 코드베이스 통째로)
- 속도가 생명인 것 (대량 배치, 즉답 UI)

한 줄: **일상의 8할은 로컬 대체 가능, 2할(긴 에이전트·최고난도 추론)은 아직 클라우드.**

## 하드웨어 가설 (결정 맥락)

- "70B 되나?"의 답은 **용량(GB)**, "70B 쓸 만하나?"의 답은 **메모리 대역폭**.
- Mac mini 진입선: **M4 Pro + 48GB(하한) / 64GB(권장)**. 기본 M4는 대역폭 절반이라 처짐.
- 단, 64GB여도 70B는 대역폭 병목으로 느림 → **실사용 만족은 24~35B급**이 중론.
- PC/게이밍 랩탑은 시스템 RAM이 아니라 **GPU VRAM**이 상한 (8GB→~8B, 16GB→~32B).

## 검증 방법 (2주 뒤 여기서)

1. 앱에서 대시보드(⌘D) → **By task type** 표를 연다 (30일 범위).
2. task 종류별 **peak ctx(최대 컨텍스트)** 와 **요청량/비용**을 본다.
   - peak ctx가 로컬 모델 윈도우 안( 예: 24~35B 흔한 32k~128k )에 들어오고,
   - 그 task가 tool use / 최전선 추론에 의존하지 않으면 → **로컬 후보**.
3. 가설 A/B와 실측을 대조해서, task별로 로컬/클라우드 판정을 아래에 채운다.
